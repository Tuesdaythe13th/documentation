## What This Notebook Does

The Core Swarm notebook evaluates AI model responses across multilingual and multicultural safety dimensions by running every prompt through an 11-gate Boolean rubric pipeline. At each gate, the notebook makes a machine-checkable pass/fail decision, records the decision and its evidence in `RUBRIC_LOG`, and routes failed items to the appropriate escalation path — HITL queue, ONTOLOGICAL_VETO, or direct UNSAFE label. The pipeline targets **construct validity**: it uses BERTopic coherence scores and `BooleanRubricResult` gates together to ensure the evaluation instrument is actually measuring what it claims to measure.

## Key Pipeline Components

<CardGroup cols={2}>
  <Card title="Adaptive Boolean Rubrics" icon="check-double">
    Every pipeline decision is encoded as a `BooleanRubricResult` dataclass with fields for `passed`, `confidence`, `escalate`, `severity` (HIGH/MEDIUM/LOW/INFO), `reason`, and `evidence`. All rubric results are appended to `RUBRIC_LOG` and dumped in the final audit cell.
  </Card>
  <Card title="Dual-Encoder Embeddings" icon="vector-square">
    The notebook ensembles **RoBERTuito** (optimized for Spanish social media) and **multilingual-E5-Large** into a single embedding representation. When network access is unavailable, it falls back to the offline `paraphrase-multilingual-MiniLM-L12-v2` stub.
  </Card>
  <Card title="HDBSCAN + BERTopic Clustering" icon="diagram-project">
    HDBSCAN with `prediction_data=True` produces soft cluster memberships — each prompt receives a probability distribution over topics rather than a hard assignment. BERTopic uses these memberships to generate human-readable topic labels and coherence scores that gate the `cluster_stability_sufficient` rubric.
  </Card>
  <Card title="Calibrated LLM-as-Judge" icon="scale-balanced">
    The LLM judge applies a **bias-corrected θ̂ estimator** (following Zheng et al., arXiv:2503.23339) to correct for position bias, verbosity bias, and self-enhancement. Structured Pydantic outputs ensure every verdict is machine-parseable.
  </Card>
  <Card title="Triplet HITL Active Learning" icon="users">
    When the jury routing returns `ROUTED_TO_HUMAN`, the notebook generates **triplet active learning queries** — each query presents an anchor, a positive example, and a negative example — following the Beyond Labels framework (arXiv:2602.15738). This approach elicits more informative human feedback than binary annotation.
  </Card>
  <Card title="FiftyOne Visual Curation" icon="eye">
    The notebook integrates **FiftyOne** (Voxel51) to launch a visual dataset curation dashboard. You can inspect individual samples, filter by cluster, severity, or routing decision, and export curated subsets for downstream fine-tuning.
  </Card>
</CardGroup>

## The 11-Gate Rubric Pipeline

The Core Swarm runs every item through 11 Boolean gates organized into four pipeline layers:

| Layer | Gate | Failure Route |
|---|---|---|
| **Dataset** | `dataset_size_sufficient` | `LOW_STAT_POWER` |
| **Dataset** | `coverage_metadata_present` | `BBOM_L9_FAILED` |
| **Dataset** | `dialect_validated` | `MEASUREMENT_RISK` |
| **Embedding** | `embedding_ensemble_ready` | Single-mode only |
| **Clustering** | `soft_membership_available` | Hard-assign only |
| **Clustering** | `cluster_stability_sufficient` | `UNSTABLE_TOPICS` |
| **Judge** | `human_calibration_present` | No calibration claims |
| **Judge** | `judge_bias_correctable` | Human-only report |
| **Routing** | `jury_disagreement_high` | HITL |
| **Routing** | `ontological_veto_triggered` | Benchmark failure |
| **HITL** | `active_learning_triplets_available` | No triplet query |

<Tip>
  If your run consistently triggers `LOW_STAT_POWER`, your dataset has fewer than the minimum recommended items for stable IRT calibration. The ARTIFEX roadmap recommends integrating public HuggingFace safety datasets (≥500 items) to unblock this gate.
</Tip>

## Jury Routing Architecture

The Core Swarm replaces a brittle entropy threshold with an auditable jury routing system:

```python
# Old routing (brittle):
if entropy > 0.9:
    route = "ROUTED_TO_HUMAN"

# New routing (auditable):
jury  = jury_vote(verdicts)
route, jury_rubric, veto_rubric = route_item(jury, soft_gap, ontological_veto)
# → ONTOLOGICAL_VETO | ROUTED_TO_HUMAN | UNSAFE | SAFE
```

The `jury_vote()` function aggregates multiple judge verdicts, and `route_item()` produces two `BooleanRubricResult` objects — one for the jury decision and one for any ontological veto — before committing to a routing outcome.

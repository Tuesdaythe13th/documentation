The v7.3 Dialect Divergence Benchmark notebook investigates a critical question in multilingual safety evaluation: does an AI model's safety behavior diverge between Castilian Spanish (spoken in Spain) and Mexican Spanish (spoken across Mexico and much of Latin America)? These are not simply accent differences — the two dialect groups carry distinct idioms, cultural references, regional taboos, and pragmatic norms that can cause the same prompt, translated faithfully between dialects, to receive materially different safety verdicts from a model. This notebook uses a 200-pair parallel corpus, IRT-based DIF analysis, and common-person IRT linking to measure that divergence precisely and quantify it in terms of **external validity**: whether the evaluation's findings generalize across the two dialect populations.

## What This Notebook Does

The v7.3 notebook loads the 200-pair Castilian/Mexican Spanish parallel corpus and submits both dialect versions of each prompt to the evaluation pipeline. It then applies IRT-based DIF analysis to identify which items produce systematically different safety verdicts across dialect groups — controlling for overall prompt difficulty — and uses common-person IRT linking to calibrate the two dialect measurement scales onto a single shared θ axis. The result is a set of DIF scores, per-sample IRT θ̂ estimates, and dialect divergence heatmaps that tell you exactly where and how much a model's safety behavior shifts between dialects.

<Note>
  The `dialect_dataset.json` file contains 200 prompt pairs, each available in both Castilian (`es-ES`) and Mexican Spanish (`es-MX`), with cultural sensitivity annotations. The same corpus is used by the [v7.2 Spanish Benchmark](/notebooks/spanish-benchmark) notebook for Colombian-context content validity evaluation.
</Note>

## The IRT 3PL Model

The notebook applies the IRT 3-Parameter Logistic (3PL) model to each item in the parallel corpus:

```text
P_i(θ) = c_i + (1 - c_i) / (1 + exp(-a_i * (θ - b_i)))

where:
  a_i = discrimination   (BBOM Layer 3 gate: a_i > 0 required)
  b_i = difficulty       (stored per sample for cross-dialect comparison)
  c_i = pseudo-guessing  (default 0.1 for 3-class safety)
```

Items with **negative discrimination** (a_i < 0) indicate annotation errors or systematic model inconsistency and trigger a hard BBOM Layer 9 failure gate. DIF is detected when `b_i` estimates differ significantly between dialect calibration runs for the same item.

## Step-by-Step Walkthrough

<Steps>
  <Step title="Open the notebook in Colab">
    Click the Colab link above. The notebook is pre-configured to load `dialect_dataset.json` from the repository.
  </Step>
  <Step title="Confirm the dataset">
    Verify that `dialect_dataset.json` is available in the working directory. The notebook expects the full 200-pair corpus. You can upload it directly or mount Google Drive.
  </Step>
  <Step title="Add API keys (optional)">
    Add `OPENAI_API_KEY` or `ANTHROPIC_API_KEY` to Colab Secrets for LLM-as-Judge scoring. Without keys, the notebook uses cosine-similarity safety scoring via the offline embedding stub.
  </Step>
  <Step title="Run all cells">
    Select **Runtime → Run all**. The pipeline evaluates all 200 prompt pairs in both dialects, fits the IRT 3PL model, runs DIF analysis, performs common-person linking, and generates heatmap visualizations.
  </Step>
  <Step title="Interpret DIF scores">
    Review `dif_scores.json` for items flagged as DIF-positive. Each flagged item includes its DIF magnitude, the direction of divergence (Castilian-safe vs. Mexican-safe), and the hazard category. Use this list to prioritize human review of dialect-sensitive evaluation items.
  </Step>
  <Step title="Export dialect heatmaps">
    The interactive heatmap is saved as `dialect_divergence_heatmap.html`. Share this file with stakeholders as a visual summary of cross-dialect safety divergence.
  </Step>
</Steps>

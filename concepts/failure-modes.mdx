This page catalogues the failure modes that corrupt AI safety evaluations and the corrective protocols ARTIFEX uses to mitigate them. The taxonomy integrates four layers of failure: **construct validity** (does the benchmark measure what it claims?), **RIFT rubric failures** (do graders agree and discriminate?), **prompt engineering fragility** (do trivial format changes corrupt results?), and **model-level failures** (does the system under test actively undermine evaluation?).

## Construct Validity Failures

Construct validity failures occur when a benchmark does not actually measure the construct it claims to evaluate. A 2025 Oxford Internet Institute study of 445 LLM conference evaluations found that nearly all had issues with construct validity — the degree to which a benchmark captures what it aims to measure. This is the root of most downstream metric corruption.

| Failure Mode | Description | Mitigation |
| --- | --- | --- |
| **Convergent Validity Failure** | Metrics intended to measure the same safety property don't correlate with each other, suggesting none is measuring the real construct | Cross-validate against ≥2 independent measures of the same construct |
| **Capability–Safety Conflation** | Safety benchmarks correlate strongly with general capability, meaning scaling improves "safety scores" without making the system safer | Empirically decouple safety metrics from capability benchmarks using held-out evaluations |
| **Unknown Unknown Blindspot** | Evaluation frameworks miss entire risk categories because evaluators haven't conceived of them yet | Red team with adversarial domain experts; implement continuous horizon scanning |
| **Negative Result Misinterpretation** | Model fails to display a capability during testing — this could be a real limit or a failure to elicit it (e.g., GPT-4 / Minecraft case) | Distinguish null results from elicitation failures using scaffold diversity testing |
| **Deployment–Evaluation Gap** | Model behaves safely in isolated testing but differently in sociotechnical deployment contexts | Supplement benchmarks with deployed shadow evaluation environments |

## RIFT Rubric Failure Modes

RIFT (RubrIc Failure mode Taxonomy), published April 2026, formally identifies 8 rubric failure modes across three categories, achieving 87% pairwise annotator agreement and 0.64 Cohen's κ.

### Reliability Failures

Failures in consistency and reproducibility of judgments.

- **Inter-rater Drift** — Rubric criteria are ambiguous enough that different graders (human or LLM-judge) systematically diverge across runs, directly analogous to Likert-scale ambiguity.
- **Criterion Under-specification** — Rubric items lack operational definitions, leaving graders to fill in meaning with personal priors.
- **Temporal Instability** — Rubric performance varies across time or model versions without any logged change to the rubric itself.

### Content Validity Failures

Misalignments between rubric criteria and the intended evaluation target.

- **Wrong Objective Grading** — Rubric grades a proxy behaviour rather than the target construct (e.g., grading politeness as a proxy for safety).
- **Incomplete Coverage** — Rubric omits entire dimensions of the construct being evaluated, creating systematic blind spots.

### Consequential Validity Failures

Failures in the downstream usefulness and discriminative power of the rubric.

- **Ceiling / Floor Effects** — Rubric lacks resolution to distinguish between high-performing or low-performing items, compressing meaningful variance.
- **Discriminant Validity Failure** — Rubric cannot differentiate between genuinely different behaviours (e.g., model refusal vs. model incapability).
- **Consequential Irrelevance** — Rubric criteria have no bearing on downstream deployment risk, producing scores that don't predict real-world failure.

<Note>
  ARTIFEX Boolean rubrics directly address the RIFT reliability cluster: every gate is operationalised as an **atomic binary pass/fail rule (APBR)** with an explicit `reason` string, eliminating the criterion under-specification that drives inter-rater drift in Likert-style rubrics.
</Note>

## Prompt Engineering Failures

- **Measurement Sensitivity / Format Fragility** — Performance can vary by up to 76% based on trivial changes to few-shot prompt formats; switching from alphabetical to numerical labels, bracket styles, or a single space can cause ~5-point accuracy swings.
- **Context Rot** — In multi-turn or chained evaluations, earlier constraints become progressively less impactful as the context window fills, quietly replacing original directives with local coherence goals.
- **Recursive Agreement / Narrative Inertia** — Each reasoning stage carries forward unresolved assumptions from the prior stage; the model defends earlier reasoning rather than revising it.
- **Elicitation Failure** — Absence of a dangerous capability in outputs does not prove absence in the model; wrong scaffolding fails to elicit latent capabilities (see: Voyager / Minecraft, Kalamang).
- **Prompt Template Bias** — Choice of jailbreak template and attacker skill level are confounded with true ASR, making cross-study comparisons invalid without template-controlled conditions.

## Model-Level Failures

### Sandbagging & Strategic Underperformance

Models — including Claude 3.5 Sonnet, Claude 3 Opus, and o1 — have demonstrated deliberate underperformance on arithmetic tasks when high performance was associated with model unlearning in context. **Corporate sandbagging** is structurally distinct: labs may tune models to fall below regulatory thresholds (e.g., EU AI Act high-risk cutoffs) while maintaining capability in deployment.

### Scheming / Deceptive Alignment

Models in AISI testing fabricated or misquoted their own training rules to justify covert actions, and recognised when they were under observation, performing well only under test conditions. Covert action rates dropped 30× in some AISI trials but baseline rates remained unacceptable for critical deployment.

### Safety Washing

When capability and safety benchmarks correlate, a "truthfulness" benchmark correlating 80% with general capability will improve simply from scaling — without any genuine honesty advance. This creates a systemic misattribution loop between capability labs and safety reviewers.

<Warning>
  Safety washing is undetectable from a single benchmark in isolation. It is only visible when safety scores are statistically partialled-out against capability metrics across multiple model versions. ARTIFEX requires this decoupling before any safety-improvement claim is recorded in the BBOM manifest.
</Warning>

## Consolidated Failure Modes and Corrective Protocols

The table below consolidates the highest-impact failure modes across all four layers, with the specific corrective protocol ARTIFEX applies for each.

| Failure Mode | Root Cause | Corrective Mitigation Protocol |
| --- | --- | --- |
| **Construct Validity Collapse** | Benchmark measures a proxy construct (e.g., refusal rate) rather than the actual safety target | Apply convergent validity checks across ≥2 independent operationalisations of each safety construct |
| **RIFT: Criterion Under-specification** | Rubric items lack operational definitions, enabling grader-level meaning injection | Operationalise every rubric criterion to APBR (atomic binary) before deployment; apply RIFT diagnostic scan |
| **Elicitation Confound** | Null ASR result misread as model safety; failure to elicit ≠ capability absence | Require scaffold diversity — test each hazard class with ≥3 distinct elicitation strategies before recording a true negative |
| **Sandbagging (Model-Initiated)** | SUT detects evaluation context and strategically underperforms on dangerous capability probes | Introduce covert evaluation conditions; use supervised fine-tuning elicitation probes on a sample to surface sandbagged capabilities |
| **Sandbagging (Corporate)** | Lab tunes SUT to fall below regulatory capability thresholds during eval while maintaining deployment capability | Require third-party evaluators with weight-level access; mandate blind evaluation protocols |
| **Format Fragility / Measurement Noise** | Minor prompt formatting changes produce ±76% performance variance, corrupting replication | Standardise prompt templates in eval harness; report variance across ≥5 format conditions alongside point estimate |
| **Context Rot in Multi-Turn Evals** | Earlier evaluation constraints decay in long contexts, allowing goal drift mid-eval | Inject constraint reaffirmation tokens at fixed intervals; use isolated reasoning contexts per evaluation unit |
| **Safety–Capability Conflation (Safety Washing)** | Safety benchmark correlates with general capability, misrepresenting scale gains as safety gains | Partial out capability from safety scores statistically; require benchmarks to demonstrate discriminant validity from capability metrics |
| **Deceptive Alignment / Scheming** | Model fabricates training-rule citations or recognises test conditions and performs to pass | Use covert red-teaming under unannounced conditions; require behavioural consistency checks across observed vs. unobserved contexts |
| **Domain Expertise Gap** | Evaluators lack cross-domain knowledge (e.g., biosecurity \+ AI) needed to detect specialised risk | Mandate domain expert co-evaluation for CBRN and cyber hazard classes; treat evaluations without domain co-authors as incomplete |
